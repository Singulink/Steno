# TypeScript

The TypeScript reference implementation of the Steno Encoding is the package `@singulink/steno`: one ES module with type declarations and no runtime dependencies, in scalar JavaScript with fast paths. It uses only standard JavaScript and `Uint8Array`, so it runs unchanged in Node.js 20 and later, Deno, Bun and browsers, and it passes all test vectors of the specification.

### Installation

> [!NOTE]
> Not published yet: the package below is the planned name.

```sh
npm install @singulink/steno
```

## First Example

```js
import { decode, encode } from '@singulink/steno';

const bytes = encode('Москва');
console.log(bytes.length); // 7
console.log(new TextEncoder().encode('Москва').length); // 12
console.log(decode(bytes)); // Москва
```

JavaScript has no built-in comparison of unsigned bytes, so the package has `compareBytes` for Steno bytes and `compareCodePoints` for strings in memory: the `<` operator and the default `Array.prototype.sort` compare UTF-16 code units, which is another order where an emoji meets U+E000..U+FFFF. `startsWith` answers a prefix query on Steno bytes.

## What Is Particular to TypeScript

| Feature | What it gives |
|---|---|
| `encodeInto` | Encoding into your own buffer; it throws a `RangeError` when the buffer is too small, instead of writing part of the text |
| `StenoEncoder`, `StenoDecoder` | One value in pieces, in the manner of `TextDecoder` with `{ stream: true }`; a call without it ends the value |
| `StenoEncoderStream`, `StenoDecoderStream` | `TransformStream`s, like `TextEncoderStream` and `TextDecoderStream` |
| `StenoDecodeError` | The rule of the specification that the bytes break, and where |
| Checked arguments | A wrong argument type throws a `TypeError` instead of being coerced into an empty or wrong result |

`STENO_ENCODING_NAME` is `x-steno`, the name to record next to the data.
