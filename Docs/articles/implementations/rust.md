# Rust

The Rust reference implementation of the Steno Encoding is the crate `singulink-steno`: no dependencies, `no_std` support, and vector code for x86-64 and ARM64 behind the `simd` feature, which is on by default; without it, the crate forbids unsafe code. It passes every test vector of the specification. The crate `singulink-steno-capi` puts a C library over it (see [C Library](#c-library)).

### Installation

> [!NOTE]
> The crates are not published yet.

```toml
[dependencies]
singulink-steno = "0.1"
```

## First Example

```rust
let bytes = singulink_steno::encode("Москва");
assert_eq!(bytes.len(), 7); // UTF-8 takes 12
let text = singulink_steno::decode(&bytes)?;
assert_eq!(text, "Москва");
```

The bytes sort like the text. Rust compares byte slices as unsigned bytes and `str` by its UTF-8 bytes, which is code point order, so Rust's own comparisons already give the order of the Steno Encoding, on strings in memory and on encoded bytes alike:

```rust
let zug = singulink_steno::encode("Zug");
let zurich = singulink_steno::encode("Zürich");
assert!(zug < zurich);     // the bytes of "Zug" sort first
assert!("Zug" < "Zürich"); // and so do the strings
```

## What Is Particular to Rust

| Feature | What it gives |
|---|---|
| `str`, UTF-16 (`&[u16]`) and code points (`&[u32]`) | `str` cannot hold a surrogate, so decoding a value that has one to a `String` fails instead of replacing it; the UTF-16 and code point forms hold every value |
| One-shot functions with `Vec`, `String` and slice forms, and true maximum lengths | Encoding into a buffer of your own, with an error instead of a panic when it is too short |
| `Encoder` and `Decoder` | One value in pieces; `finish` ends the value, `reset` starts a new one, and there is no flush. Pieces of `str`, UTF-16 and code points can be mixed. A high surrogate and a low one are joined only when both come as UTF-16 code units; any other mix of the two is rejected with `NotAValue`, so `Encoder::encode_utf16` and `encode_code_points` return a `Result` |
| `no_std` | Without the default `std` feature the crate needs only `alloc`; each call then builds its own layout cache, which makes short values outside ASCII much slower |

`WEB_NAME` is `"x-steno"`, the name to record next to the data.

## C Library

The crate `singulink-steno-capi` builds a static and a dynamic library named `steno`, with the header `capi/include/steno.h`, for C and for other languages that bind to C. Its functions are the one-shot functions of the [C reference implementation](c.md), which is plain C in two files, with the same names, signatures and status values; the streaming objects are in the C reference implementation only. Both libraries are named `steno`, so a program links one of the two. [Two Libraries, One Interface](c.md#two-libraries-one-interface) helps you choose. The [README](https://github.com/Singulink/Singulink.Steno/blob/main/Ports/rust/README.md#c-interface) shows how to build it and link a C program with it.
