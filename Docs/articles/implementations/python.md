# Python

The Python reference implementation of the Steno Encoding is the package `singulink-steno`, imported as `singulink_steno`. It is written in pure Python, with no dependencies, runs on Python 3.9 and later, and passes all test vectors of the specification. Importing it registers the codec `x-steno` with the standard library, so `str.encode` and `bytes.decode` work with the Steno Encoding as with any other codec, and the package's own `open()` reads and writes text files.

## First Example

```python
import singulink_steno as steno

data = steno.encode("Москва")
print(len(data), len("Москва".encode("utf-8")))   # 7 12
print(steno.decode(data))                         # Москва

# Importing the package registered the codec x-steno:
print("Zürich".encode("x-steno") == steno.encode("Zürich"))   # True
```

Python compares `str` values in code point order and `bytes` values as unsigned bytes, so the order of Steno bytes under `<`, `sorted()` and `min()` is the order of the strings under the same operators, and the package needs no comparison functions of its own. `bytes.startswith` on Steno bytes answers a prefix query.

```python
print(steno.encode("Zug") < steno.encode("Zürich"), "Zug" < "Zürich")   # True True
```

## What Is Particular to Python

- **Lone surrogates round-trip.** A Python `str` can hold lone surrogates, for example from the error handlers `surrogateescape` and `surrogatepass`. They are code points of their own in the Steno Encoding, so they are encoded, and decoding gives them back. The one `str` that is not a value has a high surrogate directly followed by a low one; encoding it raises `UnicodeEncodeError`.
- **Text files: use `singulink_steno.open()`.** A whole text file is one value. The package's `open()` takes only the modes that cannot write wrong bytes: `"r"`, `"w"`, `"x"`, and `"a"` on a file that is empty or does not exist. Appending to a file that is not empty raises `io.UnsupportedOperation`, because the bytes of new text depend on all the text before it; the modes with `"+"` raise `ValueError`.

    ```python
    with steno.open(path, "w") as f:
        f.write("Москва\n東京\n")

    with steno.open(path) as f:
        print(f.readlines())   # ['Москва\n', '東京\n']
    ```

- **The built-in `open()` with `encoding="x-steno"` is safe for reading and for writing a new file** (`"w"`, `"x"`, or `"a"` on an empty file). It is not safe in the modes `"r+"`, `"w+"` and `"a+"`: a write after a read starts a new value in the middle of the file, which cannot be read back. Use the package's `open()` instead.
- **Flushing is safe.** The encoder never holds text back, so `flush()` in the middle of a file writes a prefix of the final bytes; writing, flushing and writing more gives the same file as one write.
- **`tell()` and `seek()` work for reading.** `seek(0)` always works, and in the same process a position from `tell()` restores exactly. The one rare exception is a position in Chinese, Japanese or Korean text right after a character of another script: the process remembers the last 65,536 such positions, and a `seek()` to one it has forgotten raises `io.UnsupportedOperation`. In another process, such a position is refused or, with a small chance, accepted wrongly. To keep positions across runs, store the byte offsets of the starts of values instead.
- **Only the error handler `"strict"`.** Any other raises `ValueError` at once: after invalid bytes the state is unknown, so no handler could replace them and go on. Invalid bytes raise `StenoDecodeError`, a subclass of `UnicodeDecodeError`, with the rule of the specification that they break and where.
- **No byte order mark.** The codec neither writes nor removes one: U+FEFF is an ordinary code point.

| Feature | What it gives |
|---|---|
| `encode`, `decode` | One whole value, from `str` to `bytes` and back; `decode` takes any object with the buffer protocol |
| `Encoder`, `Decoder` | One value in pieces: the incremental encoder and decoder of the codec; `final=True` ends the input, `reset()` starts a new value |
| `is_ascii_text` | Tells from the bytes alone whether a value has only tab, line feed, carriage return and U+0020..U+007E |
| `max_encoded_len`, `max_decoded_len` | True bounds for the size of the result |
| `StenoDecodeError` | The rule of the specification that the bytes break (`reason`) and where (`offset`) |

`ENCODING_NAME` is `x-steno`, the name to record next to the data.
