# Steno or SCSU?

**The Steno Encoding (Steno for short) is smaller than SCSU over every group of values measured, and smaller or tied in 552 of the 565 sets of values (one language or text at one length of value); it also keeps the order, the prefixes and one encoding per text, which SCSU does not.** The gap in size is small (SCSU is 0.6% to 7% larger over each group) and largest on short values (21% in Greek at 4 characters). Choose Steno when a store must compare, sort or hash the bytes; SCSU suits text that is stored and read back whole where a Unicode standard is required.

## Why Choose Steno over SCSU

- **Bytes that a store can work on.** Steno bytes sort in code point order (the order of the characters' Unicode numbers), keep prefixes and have one encoding per text. SCSU bytes have none of the three: an SCSU encoder chooses where to place its tags, so the same text can have several encodings, and the bytes do not sort like the text. A store that keeps SCSU must decode a value to compare it, and equal text has equal bytes only while one encoder writes them all.
- **Smaller, most of all on short values.** On 4-character values SCSU is 21% larger than Steno in Greek, 16% in the Indic scripts, 7% in Arabic script and 7% in Korean; on 16-character values it is 18% larger in Japanese and 13% in Korean.
- **No 00 byte.** SCSU's Unicode mode writes UTF-16 code units, which can contain 00; Steno never writes 00.
- **Line feeds and tabs that can be found in the bytes.** In Steno the byte 03 is always a line feed and 02 always a tab, so encoded text can be split into lines and fields without decoding it, and Steno values can be kept one per line or in tab-separated data. In SCSU these byte values can be part of other characters.
- **Faster to encode** in the .NET measurements ([Speed, Head to Head](#speed-head-to-head)). ICU is called from .NET once per value, which costs most on short values; another SCSU implementation may be faster.

## Where SCSU Is the Better Choice

- **Smaller on scripts that span several windows.** A window is the run of up to 128 code points, usually the letters of one script, whose code points take 1 byte. On Amharic and Urdu paragraphs and documents, whose scripts span more than one window, SCSU is 2% to 9% smaller than Steno; on text dense with typographic punctuation and symbols it is up to 1% smaller. SCSU moves its windows with tag bytes, which suits such text and is also why its bytes keep neither the order nor one encoding per text.
- **Faster to decode some documents**, in the .NET measurements ([Speed, Head to Head](#speed-head-to-head)).

## Properties

| | SCSU | Steno |
|---|---|---|
| Bytes sort in code point order | No | Yes |
| Prefix of the text, prefix of the bytes | No | Yes |
| One encoding per text | No: the encoder chooses | Yes |
| No 00 byte | No | Yes, U+0000 included |
| Line feed, tab, carriage return and space bytes never part of another character | No: in Unicode mode, and after a quote tag, the bytes are UTF-16 code units, and any byte value can be one of them | Yes: 03 is always a line feed, 02 a tab, 05 a carriage return and 07 a space ([§13.5](../reference/specification.md#135-no-byte-below-08-inside-a-code-point)) |
| Specification | Unicode Technical Standard #6 | Steno Encoding, version 1, an open specification, free to implement |
| Implementations | ICU and other libraries | Reference implementations in .NET, Rust, C, Go, Java, TypeScript and Python |

## What It Means for a Store

These follow from the measured sizes and properties; none of them was measured in a database.

- **No decoding to compare.** With Steno, a store compares, sorts and range-scans the bytes; with SCSU it must decode both values first, which in the .NET measurements takes many times as long as comparing the bytes ([Comparing Without Decoding](../benchmarks/comparing.md)).
- **About the same space (calculated).** On 16-character values the two fit about the same number of values in a page in alphabets (544 against 539 Latin values in 8 KB), and Steno fits more in Japanese (387 against 329) and Korean (338 against 299).

## Choosing

- **Choose Steno when** a store keeps the text as values or keys and compares, sorts, prefix-matches or hashes them as bytes.
- **Choose SCSU when** a system already reads or writes SCSU, or for Amharic or Urdu documents that are stored and read back whole where a general compressor is not an option.
